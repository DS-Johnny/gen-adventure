# INTERACTIVE STORY GENERATION INSTRUCTIONS FOR JSON

## OBJECTIVE

Create an interactive story in JSON format using UTF-8 encoding.

The story must contain exactly N pages (40 by default unless another number is explicitly requested).

Each page represents a node in a decision graph.

The player progresses through the story by selecting choices that lead from one page ID to another until reaching pages without options (endings).

## LANGUAGE RULE

* If the requested theme is written in English, the entire story must be written in English.
* If the requested theme is written in Portuguese, the entire story must be written in Portuguese.
* All narrative text, dialogues, descriptions, endings, and choices must consistently follow the language of the requested theme.
* Never mix languages unless the theme explicitly requires it.

## JSON STRUCTURE

The output MUST be a valid JSON object.

The root object MUST contain a single property named:

"pages"

Example:

{
"pages": [
{
"id": 1,
"text": "Story text",
"options": [
{
"text": "Choice A",
"target": 2
},
{
"text": "Choice B",
"target": 3
}
]
}
]
}

## PAGE STRUCTURE

Each page object MUST contain:

1. id

   * Integer
   * Sequential
   * Starts at 1
   * Ends at N

2. text

   * String
   * Contains the narrative for the page
   * May include descriptions
   * May include dialogues
   * May include emotional and sensory details
   * Should naturally lead to a decision unless it is an ending

3. options

   * Array
   * Contains zero or more choice objects

## CHOICE STRUCTURE

Each choice object MUST contain:

1. text

   * String
   * Text displayed to the player

2. target

   * Integer
   * Destination page ID

Example:

{
"text": "Enter the abandoned building",
"target": 7
}

## ENDING PAGES

Ending pages MUST contain:

"options": []

Example:

{
"id": 40,
"text": "The adventure ends with your final discovery.",
"options": []
}

## MANDATORY VALIDATION RULES

1. IDs

* IDs must be sequential.
* IDs must start at 1.
* IDs must end at N.
* No missing IDs.
* No duplicated IDs.

2. Targets

* Every target must reference an existing page.
* No target may point outside the range 1..N.

3. Reachability

* Every page must be reachable from page 1.
* No isolated pages.
* The graph must be connected.

4. Endings

* The story must contain at least one ending.
* Endings must use:

  "options": []

5. Structural Consistency

Every page must contain:

* id
* text
* options

No additional fields are allowed.

## VALID PAGE EXAMPLE

{
"id": 12,
"text": "The corridor becomes darker as you move forward. A strange sound echoes from somewhere ahead. What do you do?",
"options": [
{
"text": "Investigate the sound",
"target": 13
},
{
"text": "Return to the entrance",
"target": 8
}
]
}

## VALID ENDING EXAMPLE

{
"id": 40,
"text": "You successfully escape the facility and expose the conspiracy to the world.",
"options": []
}

## INVALID EXAMPLE

{
"id": 12,
"text": "The corridor becomes darker.",
"choices": [
{
"text": "Continue",
"target": 13
}
]
}

Reason:

The property must be named:

"options"

not

"choices"

## INTERACTIVE NARRATIVE BEST PRACTICES

* Cause and effect: every choice should lead to a coherent result.
* Replayability: include multiple endings and hidden paths.
* Memorable characters: use distinctive dialogue.
* Pacing: alternate between action, dialogue, and introspection.
* Surprises: include twists and unexpected revelations.
* Avoid narrative bias: no choice should appear obviously correct or incorrect.
* Maintain thematic consistency with the requested universe.

## STORY QUALITY REQUIREMENTS

Each page should:

* Advance the narrative.
* Provide meaningful information.
* Present interesting choices.
* Maintain immersion.
* Respect the chosen theme.

Dialogues should:

* Sound natural.
* Match the personality of the characters.
* Help develop the story.

Descriptions should:

* Include sensory details when appropriate.
* Create atmosphere.
* Support immersion.

## DECISION GRAPH REQUIREMENTS

The story should contain:

* Branching paths.
* Multiple routes.
* Multiple endings.
* Meaningful consequences.
* Opportunities for replayability.

Avoid:

* Excessive dead ends.
* Long chains of meaningless choices.
* Repetitive pages.
* Choices that immediately converge without narrative impact.

## INSTRUCTIONS FOR THE AI AGENT

1. Receive the story theme from the user.
2. Generate exactly N pages.
3. Create IDs from 1 to N.
4. Build a connected decision graph.
5. Use descriptions, dialogues, emotions, and plot twists.
6. Create multiple endings.
7. Ensure every target ID exists.
8. Ensure every page is reachable from page 1.
9. Ensure all pages follow the required JSON structure.
10. Produce valid UTF-8 compatible JSON.

## JSON COMPATIBILITY (CRITICAL)

IMPORTANT:

The output will be loaded using:

json.loads()

Therefore:

* Output MUST be valid JSON.
* All property names MUST use double quotes.
* All string values MUST use double quotes.
* No trailing commas.
* No comments.
* No markdown.
* No code blocks.
* No explanations.
* No additional text before the JSON.
* No additional text after the JSON.

## VALIDATION CHECKLIST

Before generating the final output verify:

✓ Output is valid JSON

✓ Root object contains "pages"

✓ Number of pages equals N

✓ IDs are sequential

✓ IDs start at 1

✓ IDs end at N

✓ Every page contains:

* id
* text
* options

✓ Every option contains:

* text
* target

✓ Every target exists

✓ Every page is reachable from page 1

✓ At least one ending exists

✓ Endings use:
[]

✓ JSON is compatible with json.loads()

## FINAL OUTPUT RULE

Return ONLY the JSON object.

Do not explain anything.

Do not use markdown.

Do not use code blocks.

Do not add comments.

Do not add additional text.

The first character of the response must be:

{

The last character of the response must be:

}
